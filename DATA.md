# Data layout

No data ships with this repository. Every path below is read relative to
the repository root, so create a `data/` folder there matching this layout
exactly (paths in **bold** are the ones the code opens directly; everything
else is folder structure).

None of this is anonymized/synthetic — it is real station/counter data, so
treat it accordingly (do not commit it; keep it out of version control,
e.g. via `.gitignore`).

## `data/meteo/` — weather stations (9-fold split, `k=8` → folds `i=0..8`)

- **`data/meteo/stations_curated_sorted.json`** — full station metadata (keys
  are `id_XXXX` matching the timeseries filenames; each entry needs at least
  `x`, `y` projected coordinates and an `idx`).
- **`data/meteo/stations_curated_sorted_REAL_K=8_i={0..8}.json`** — per-fold
  metadata for the "real" (observed) station subset, 9 files.
- **`data/meteo/stations_curated_sorted_VIRTUAL_k=8_i={0..8}.json`** —
  per-fold metadata for the held-out ("virtual") station subset, 9 files.
- **`data/meteo/timeseries/*.csv`** — one CSV per station, filename ending in
  the 4-digit station id (matched via `id_<last 4 chars of filename>`).
  Expected columns include `povp. T`, `povp. rel. vla.`, `količina padavin`,
  plus precomputed `daytime_sin/cos`, `yearday_sin/cos`.
- **`data/meteo/graph/<graph_name>/edgelist.nx`** — `networkx` weighted
  edgelist per named graph variant. Needed graph names:
  - `elev_distance_3500_distance_30000_corr_0975` (base/hyperparameter sweep)
  - `elev_distance_3500_distance_30000_corr_0975_REAL_K=8_i={0..8}` (9 fold graphs)
  - `elev_distance_3500_distance_30000_corr_0975_fullHigherBenchmarks` (full graph)
- **`data/meteo/dtm/dtm.npy`** — digital terrain model raster (elevation).
- **`data/meteo/sentinel/sentinel2_data.npy`** — Sentinel-2 raster stack
  (channel 11 = SCL, channel 12 = NDVI source, per `data_handling/grid.py`).

## `data/traffic/` — motorway traffic counters (10-fold split, `k=10` → folds `i=0..9`)

- **`data/traffic/counters_consolidated.json`** — full counter metadata.
- **`data/traffic/preproc/consolidated/*.csv`** — one CSV per counter,
  filename ending in the 6-character counter id. Expected columns include
  `slow`, `fast`, `VAvg`, `VMin`, `VMax`, `Gap`, `Occ`, `Status`, calendar
  features (`yearday_sin/cos`, `weektime_sin/cos`, `daytime_sin/cos`),
  holiday flags (`praznik_<Country>`), weather (`povp. T`, `kolicina padavin`,
  `povp. rel. vla.`), and `event_*` one-hot event columns.
- **`data/traffic/metadata/k_fold/{0..9}.json`** — per-fold "real" counter
  metadata, 10 files.
- **`data/traffic/metadata/k_fold/{0..9}_v.json`** — per-fold "virtual"
  (held-out) counter metadata, 10 files.
- **`data/traffic/graph/k_fold/{0..9}/edgelist.nx`** and
  **`edgelist_expw.nx`** — per-fold graphs (base weights and exponential
  road-distance weights — the latter generated by
  `data_handling/generate_expw_graphs.py`).
- **`data/traffic/graph/consolidated/edgelist.nx`** and **`edgelist_expw.nx`**
  — full consolidated graph, both weight variants.

Node/edge metadata also expects per-counter fields: `onehot_smer1/2`,
`speed_limit`, `onehot_AC`, `onehot_HC` (used as `METADATA_FEATURES`
context).

## `data/air/` — air-quality stations (8-fold split, `k=8` → folds `i=0..7`)

- **`data/air/stations_curated.json`** — full station metadata.
- **`data/air/enriched/*.csv`** — one CSV per station, filename ending in the
  4-character station id. Expected columns include `NO2`, `O3`, `PM10`,
  weather (`povp. T`, `kolicina padavin`, `povp. rel. vla.`, `hitrost_vetra`,
  `povp_tlak`), and calendar features.
- **`data/air/metadata/k_fold/{0..7}.json`** — per-fold "real" station
  metadata, 8 files.
- **`data/air/metadata/k_fold/{0..7}_v.json`** — per-fold "virtual" station
  metadata, 8 files.
- **`data/air/graph/k_fold/{0..7}/edgelist_inv.nx`** — per-fold graphs.
- **`data/air/graph/full/edgelist_inv.nx`** — full graph.
- **`data/air/metadata/contextual_features_normalized.csv`** — per-station
  contextual feature table indexed by station id, providing the
  `METADATA_FEATURES` columns (settlement distance/elevation/population,
  large combustion plant — `lcp_*` — proximity/emissions, NDVI, building
  coverage, plus rolling per-pollutant stats `<pollutant>_mean/std/p5/p95/daily_fluct`).

## Notes / things to double check when sourcing this from the larger project

- `hyperparams_air.py`'s `__main__` block and the rest of the "air"
  scripts used two *different* paths for what looks like the same full
  station-metadata file (`arso_air/data/metadata/arso_air_postaje_curated.json`
  vs. `tools/arso_air/arso_air_postaje_curated.json`). Both were normalized
  here to `data/air/stations_curated.json` — please confirm that's actually
  the same file before copying data over, otherwise `hyperparams_air.py`
  needs pointing at a second file.
- `interpolation_meteo.py` imported a `phd_hyperparams` module that does not
  exist anywhere in this codebase (only `phd_hyperparams_residual.py` did,
  itself since renamed to `hyperparams_meteo.py`). It's been repointed to
  `hyperparams_meteo.py`, assuming that was always the intent — flag if that
  assumption is wrong.
- The `data/traffic/graph/*/edgelist_expw.nx` files are *generated* (not
  raw data) by `data_handling/generate_expw_graphs.py`
  from `edgelist.nx` + `counters_consolidated.json`. You only need to source
  the base `edgelist.nx` graphs and can regenerate the `_expw` variants by
  running that script once the base data is in place.
